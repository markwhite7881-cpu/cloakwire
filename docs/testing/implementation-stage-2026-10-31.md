# Первый этап реализации: данные, импорт и маршрутизация

Последующий этап: [установка и проверки на реальном Android](android-device-2026-10-31.md). Ниже сохранён отчёт первого этапа до подключения телефона.

Дата: 2026-10-31. Ветка: `feat/connection-reliability-ux`.
Проверенный коммит кода: `fb3ea5b`. Основа: `f541c28` (исходники приложения 1.4.9).
Это промежуточный этап [утверждённого плана](../superpowers/plans/2026-10-31-reliability-and-ux-roadmap.md). Весь план не завершён, релиз не подготовлен.

## Что реализовано

- Ручные профили получили постоянные локальные ID и ревизии. Миграция сохраняет совместимую копию для 1.4.9; правки после отката обнаруживаются и требуют выбора источника или объединения.
- Повторный импорт предлагает обновить конкретную запись, добавить отдельно или пропустить. Совпадение адреса не заменяет другой аккаунт автоматически. Сохраняются имя, положение, выбор и существующие цели правил.
- Сравнение показывает категории изменений без значений ключей. Одинаковые имена различаются безопасными локальными метками, одинаковыми в диалоге и списке серверов.
- Ошибка записи сохраняет ввод и диалог. Устаревшие записи и решения об объединении не перезаписывают свежие данные. Отказ хранилища блокирует переподключение до остановки работающей сессии.
- Удалённый выбранный профиль требует нового выбора; он не превращается в Auto, в том числе после перезапуска.
- Режимы «все», «только выбранные», «кроме выбранных» применяются отдельной кнопкой. Сохранённые списки возвращаются при смене режима. Дополнительные правила, DNS и настройки провайдера не нормализуются при открытии экрана.
- Android использует прежнюю политику захвата пакетов приложений. Desktop показывает ограничение Xray для маршрутизации по процессам.
- Все новые сообщения переведены на RU/EN/zh-CN.

## Независимое ревью

Один отдельный reviewer проверил f541c28..63d544d. Исправлены пять существенных замечаний: устаревшее объединение/Retry, конфликтующие имена после merge, устаревший guard переподключения, удаление выбранного профиля и неразличимые кандидаты импорта. Дополнительно повышено до существенного замечание о cleanup тестовых ядер: неподтверждённая остановка теперь запрещает PASS и следующие запуски.

Для исправлений наблюдался провал соответствующих тестов, затем успех. Полный frontend и браузерный набор после исправлений проходит. Повторное ревью не проводилось.

Небольшое отложенное замечание: если отредактировать ещё не применённый список приложений, переключить предлагаемый режим и вернуться, эти неприменённые правки теряются. Ранее применённые списки сохраняются; действующая маршрутизация до Apply не меняется.

## Решения и ограничения

- Сохранены ID задач D0/B1 и ручной ledger вместо перенумерации под скрипт; риск — дополнительный ручной учёт.
- Android JVM запускается через фактический flavor `:app:testArmDebugUnitTest`; исходное имя задачи было неоднозначным.
- Без тестового Android/Windows VM продолжена независимая работа с данными/UI; native gates не считаются пройденными. Цена — неполная поставка всего плана.
- Node harness отделён от Vitest; отдельный scoped exclude не скрывает тесты приложения.
- События проверяют также operation_id, чтобы поздний повтор одной проверки не заменял актуальный результат.
- Локальный FNV checksum служит обнаружению изменений, не аутентификации; содержимое дополнительно сравнивается целиком. Он не публикуется.
- Изолированная Xray-копия отклоняет неподтверждённую DNS-привязку. Цена — часть профилей пока нельзя проверить.
- Desktop/mobile используют общую модель импорта; мобильный диалог использует существующий Sheet. Сохранение подтверждается до очистки ввода.
- Удалена повторяющаяся эвристика direct→proxy в загрузчике v2: она меняла явно сохранённую политику. Очень старые установки с прежним ошибочным default теперь требуют явного выбора режима.
- Браузерный набор проверяет собранные файлы через preview: dev-server нестабильно задерживал загрузку mobile. Новых зависимостей не добавлено.
- Неподтверждённая остановка owned child блокирует дальнейшие кейсы; временные файлы сохраняются до доказанной остановки.
- Live probe attribution/DNS/interface/accepted identity остаются неподключёнными; Android concurrency/Activity recovery не подтверждены.
- Runtime ошибки, health UI и recovery ожидают native зависимости; ложный успешный probe и frontend retry owner не добавлялись.
- Полная визуальная, системная и пакетная приёмка не заменяется mock-тестами. Отдельное распоряжение о выпуске по-прежнему необходимо.

Журнал работы и исходные результаты находятся в локальной игнорируемой папке `.superpowers/sdd/2026-10-31-reliability-and-ux-roadmap/`. Её не следует удалять до продолжения незавершённых native этапов.
