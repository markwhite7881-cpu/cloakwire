- Исходный VLESS Reality сервер отвечает через sing-box до и после обновления. Проверка использовала сохранённые данные только на устройстве/в локальном процессе, без записи секретов в отчёт или fixtures.
- Ошибочные кандидаты sing-box и Xray отвергаются с `profile_check_unsupported`, сохраняя работающий VPN.

- Для sing-box и Xray: «только выбранные» захватывает тестовое приложение, «кроме выбранных» оставляет его вне VPN; HTTPS 204 проходит в обоих случаях.

- Некорректная ссылка раньше показывала `[object Object]`. Исправлено использование структурированной причины; на итоговом APK проверены читаемая ошибка, сохранение ввода и отсутствие изменений профилей/VPN.

Xray проверялся конфигурацией, созданной существующим генератором из выбранного ручного профиля. Произвольные готовые конфигурации провайдеров этой проверкой не покрыты. Утверждение о захвате приложений не заменяет полную проверку DNS/UDP/правил доменов и внешнего IP каждого профиля.

## Принятое поведение при принудительном закрытии задачи

Пользователь подтвердил, что такое отключение его устраивает; менять это поведение не нужно, оно не блокирует дальнейшую работу.

При принудительном уничтожении задачи и создании нового окна (`am start -f 0x10008000`) старый процесс Cloakwire спустя короткую задержку завершается с EXIT_SELF. Вместе с ним обрывается VPN; при следующем запуске он восстанавливается. Первое немедленное чтение статуса ошибочно выглядело успешным, но последующая сетевая проверка и история завершения процессов выявили обрыв.

Это **не** доказательство сбоя при обычном сворачивании или вызове Android `Activity.recreate()`: проверялось именно удаление/создание задачи. Этот случай теперь отмечен отдельно, а не зелёным результатом основной матрицы.

В текущих Tauri 2.11.5/tao 0.35.3 уничтожение последнего окна по умолчанию завершает общий процесс. Такой запуск через `.run(generate_context!())` присутствует также в исходниках 1.4.7. Аналогичное поведение и дополнительная проблема пустого WebView при простом `prevent_exit()` описаны в [upstream issue 15671](https://github.com/tauri-apps/tauri/issues/15671). Однострочный запрет выхода не применялся: требуется проверить восстановление самого окна и намерение пользователя при закрытии задачи.

Настоящие отдельные процессы диагностики libbox, их DNS/socket isolation, полноценное пересоздание Activity, отмена через Binder, Hysteria2/TUIC и автоматическое восстановление остаются незавершёнными этапами D3/C3. Наличие телефона снимает прежний аппаратный блокер, но не является доказательством этих свойств.
