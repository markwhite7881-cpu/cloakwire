# Android: спокойная проверка серверов — 2026-11-01

Исправление UX после checkpoint 268737a. Пользователь сообщил, что при смене сервера проверка выглядит ошибочной, ручная проверка проходит, надписи отвлекают и результат пропадает.

## Что удалось воспроизвести

На установленном APK, при работающем sing-box:

- после смены выбранного сервера native snapshot сетевой проверки был пуст;
- карточка стала показывать «Не проверен»;
- после возврата к исходному серверу в ней появился устаревший результат **preflight**, хотя отдельного сетевого результата в native snapshot не было;
- VPN остался running с прежним run ID.

Циклический автоматический запуск сетевой проверки не воспроизведён. Неудача нового сетевого запроса при одной лишь смене выбора также не наблюдалась. Подтверждённые проблемы — потеря результата и смешение проверки конфигурации при подключении с проверкой доступа в одной карточке. Эти состояния выглядели как требование постоянно проверять сервер заново.

## Изменения

- Завершённые измерения хранятся отдельно по источнику и ревизии; смена выбора не стирает прошлый результат.
- История хранится в текущей сессии интерфейса, ограничена 100 записями. После перезапуска приложения постоянный архив не обещается.
- Старый результат сохраняет время, исход и причину. Он обозначается прошедшим временем («Был доступен»), а не утверждением о текущей доступности; смена DNS/сети не возвращает старый зелёный статус.
- Проверка нового кандидата и активного VPN остаются разными понятиями. Старый ответ не может стать результатом другого источника или изменённого профиля.
- Карточка ручной проверки показывает только сетевые результаты. Результаты preflight продолжают обслуживать запуск и его карточку ошибки.
- У непроверенных серверов нет постоянной подписи «Не проверен». Карточка стала компактнее; причины ручной неудачной проверки открываются через «Подробнее».
- Ошибка фонового чтения snapshot не создаёт сообщение пользователю, который не запускал проверку.
- Сетевые проверки по-прежнему запускаются кнопкой. Нативные ядра, правила маршрутизации и процедура подключения не менялись.
- RU/EN/zh-CN обновлены.

## Регрессии и независимое ревью

До исправления получены ожидаемые провалы:

- возврат к проверенному A после B теряет измерение;
- истечение 60 секунд показывает предупреждение об устаревшей проверке вместо последнего результата;
- карточка доступности показывает результат preflight;
- непроверенные строки заполняются диагностическими подписями.

Независимое ревью нашло 1 Important и 1 Minor; оба исправлены:

1. Старый native snapshot другого профиля мог попасть в историю до загрузки источников, затем показать чужую причину при выборе Auto. Browser RED (Details count 1 вместо 0) → проверка принадлежности перед восстановлением и при чтении истории.
2. Изменение default_outbound при выборе сервера могло сохранять значок истории, но терять подробную причину. Unit RED (null вместо исходного failure) → единый поиск истории по источнику и его ревизии.

Новых отложенных замечаний по этому исправлению нет. Reviewer не выполнял команд на телефоне.
