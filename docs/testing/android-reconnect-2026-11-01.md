# Android: первая попытка переподключения — 2026-11-01

Исправление поверх 40d3a98. Предыдущий UX checkpoint проверял смену выбранной строки и ручную сетевую диагностику; он не воспроизводил нажатие «Переподключить сейчас». Поэтому главная ошибка пользователя осталась.

## Причина, подтверждённая на телефоне

При переподключении обычного/ссылочного профиля MobileApp использовал общий helper stop → start. После Stop Android сбрасывал run ID. Затем замыкание connectWithSelection отправляло Start с expectedRunId уже остановленной сессии.

Native matchesRun закономерно отклонял запрос; исключение превращалось в безопасный profile_check_failed. Повторный клик из нового React-render уже использовал состояние stopped и поэтому проходил. Сетевая проверка выбранного профиля в этой последовательности не участвовала.

На исходном APK 71DA58EDAB1CAA2B80EA5D5D0FC34BD90A5E0ACA6737C885A1FEE65DB3DC7F75 воспроизведено:

- один Stop и один Start от первого нажатия;
- Start с идентификатором исходной сессии;
- результат stopped / profile_check_failed, новый run не принят;
- ноль вызовов отдельной сетевой проверки;
- после эксперимента исходное подключение и точный конфиг восстановлены.

Вызовы наблюдались CDP debugger, без попытки подменять защищённую Android invoke-функцию.

## Изменение

Android reconnect теперь передаёт новый профиль существующему native start без предварительного Stop. Android уже проверяет оба типа профилей при живом старом VPN. После успешного preflight служба сама принимает новый источник, завершает старое ядро и запускает новое.

Проверка expectedRunId и отмена незавершённой подготовки сохраняются. Автоматических повторных Start, обхода preflight или вызова сетевой диагностики не добавлено. Общий desktop helper не менялся.

Изменение ограничено reconnect-путём MobileApp; новая автосмена сервера при простом выделении строки не добавлялась. Исправляется первая попытка применения выбранного сервера.

## Регрессии

Два browser-теста воспроизвели ошибку до исправления:

1. Одно нажатие Reconnect не принимало Second: исходный VPN уже stopped, старый expectedRunId отклонён.
2. Даже ошибочный новый профиль заранее выключал старый VPN.

После исправления оба проходят: один Start против принятой сессии, ни одного предварительного Stop/сетевого probe; правильные ID и имя нового сервера приняты. Отклонённый кандидат оставляет прежний running run.

Независимое read-only ревью: 0 Critical, 0 Important, 0 Minor. Нативные ownership-проверки и момент teardown просмотрены; reviewer не запускал телефонные тесты.

На физическом CPH2747 / Android 16 установлен новый APK. При работающем sing-box выбран другой сервер и один раз нажато «Переподключить сейчас»:

- один Start с идентификатором исходной действующей сессии; ноль предварительных Stop и отдельных сетевых probe;
- новый run принят, имя и source соответствуют выбранному серверу;
- состояние running, preflight passed, error null;
- HTTPS 204 из отдельного обычного приложения проходит через VPN до и после переключения; сеть не менялась во время каждого измерения.

После теста read-only проверкой подтверждены running, точное совпадение исходного конфига, имени, source, профилей, настроек и выбора сервера с резервной копией этого испытания. Временное приложение проверки удалено, ADB forwards отсутствуют.

Сохранение старого VPN при отклонённом кандидате проверено browser-регрессией и просмотром native guards. Этот конкретный телефонный прогон выполнен с sing-box; отдельный прогон reconnect на Xray в этом checkpoint не выполнялся. Нативные Rust/Kotlin исходники не менялись, старые native suites не считаются свежим прогоном.
