# Восстановление соединения — 2026-11-01

Работа поверх 9490ce0 в feat/connection-reliability-ux. Пользователь сообщил, что проверил предыдущие изменения, и поручил сразу перейти к C1–C3: восстановлению после сна и смены сети. Его проверка не подменяет испытания новой реализации.

## Поведение

- Отдельная настройка «Автовосстановление VPN», выключена по умолчанию и для старых установок. Она не меняет профиль, маршрутизацию или выбранный сервер.
- Native-служба сохраняет принятые параметры подключения. Изменённые записи подписок, настройки интерфейса и конфиги на диске не становятся источником фонового переподключения.
- Событие сети/пробуждения сначала даёт текущему ядру возможность восстановиться. Перезапуск разрешён при подтверждённом завершении принятого ядра либо после двух проверок работающей сессии и отдельной успешной проверки того же узла в текущей физической сети.
- Одна попытка за раз, максимум три. Первый запуск — после 2 секунд ожидания события; последующие — не раньше чем через 5/15 секунд после завершения предыдущей попытки. Новый сетевой callback не пополняет лимит. Сброс лимита требует 60 секунд подтверждённой стабильности.
- Ручное отключение, новое подключение и отключение настройки отменяют старую работу. Отклонённый кандидат сохраняет работающую сессию и её параметры восстановления.
- Проверка выбранного сервера остаётся ручной. В интерфейсе служебные проверки идут тихо; показываются реальное восстановление и конечная ошибка с подходящим действием.

## Платформы

Windows/macOS используют нативные события питания/маршрутов и существующего владельца процесса. Восстановление не вызывает новые запросы повышения прав. Настройки защиты Windows/macOS не менялись. Изменение узла через runtime selector снимает право на восстановление старого снимка: текущий VPN продолжает работать, а новое ручное подключение снова фиксирует допустимый снимок. Для desktop Xray независимая проверка кандидата по-прежнему ограничена существующей гарантией привязки к интерфейсу: восстановление разрешается при подтверждённой смерти ядра, неопределённость живой сессии не считается разрешением.

Android объединяет новые попытки и смерть ядра в одном владельце, сохраняет TUN/политику приложений и использует отдельный приватный процесс проверки кандидата. Выключенная настройка сохраняет прежнее ограниченное восстановление Xray после завершения процесса. Для выбранного manual-профиля добавляется один приватный listener; фактический узел до/после запроса подтверждается свежим ответом libbox. Для Auto подготовка ограничена восемью listener. Несовместимые/неоднозначные конфигурации не получают ложного подтверждения доступа.

## Реальный телефон

CPH2747, Android 16, arm64. Тесты выполнены на установленном итоговом APK. HTTPS измеряет отдельное приложение с обычным UID: WebView CloakWire исключён из VPN и не используется как доказательство пользовательского трафика.

- Xray: точное завершение принадлежащего сессии процесса сигналом SIGKILL → одна попытка восстановления примерно через три секунды. Сохранены source, имя, run и Android VPN Network handle; HTTPS 204 через VPN до/после прошёл. Это подтверждает сохранение VPN-сети в данном сценарии, а не полную матрицу отсутствия утечек.
- Xray: повторное завершение + немедленный Stop → через семь секунд состояние stopped, принадлежащего сессии Xray нет, позднего перезапуска нет.
- Xray: screen off/on → тот же процесс/run, HTTPS работает. Wi-Fi выключен и включён обратно → HTTPS через VPN проходит в обоих состояниях; сохранены VPN Network handle/source, на промежуточном этапе attempts=0.
- Sing-box: два сохранённых manual-профиля, выбран конкретный узел. Проверка с актуальным ответом libbox завершилась без ошибки и без restart; HTTPS через VPN работает. После screen off/on те же run/source/VPN Network handle, attempts=0, HTTPS проходит.
- После каждого сценария восстановлены исходные config, engine, source, имя, профили, выбор, настройки и recovery preference. Финальная сверка включает native-настройку восстановления; она выключена, как до тестов.
- Wi-Fi возвращён в исходное состояние. Тестовый помощник удалён у user 0, диагностических процессов и временных ADB forwarding нет. На телефоне оставлен проверенный новый debug APK.

Первый опыт с SIGTERM не дождался нового процесса за 30 секунд и не содержал достаточных наблюдений для установления причины. Следующий SIGTERM восстановил подключение, но добавленная диагностическая запись выявила неверный индекс в самом тестовом runner. Индекс исправлен; итоговый SIGKILL/Stop-прогон прошёл. Системное чтение ifindex запрещено на этом Android; сохранность сети проверена доступным Android Network handle из отдельного UID. Эти промежуточные результаты не скрываются и не выдаются за исправленные продуктовые ошибки.

## Границы приёмки

Реальные sleep/wake и смена интерфейсов на Windows/macOS ещё не проверены; рабочая сеть Windows-ПК не менялась. На телефоне не выполнена полная матрица include/exclude, always-on/lockdown, Stop в середине каждой фазы и все варианты provider/Auto-конфигов. Полная выпускная матрица, старые Android/lockdown, готовые подписанные пакеты и публичный релиз остаются C4–C5. Версия не менялась, push/merge/release не выполнялись.

Профили, ключи, исходный APK и точные резервные копии телефона хранятся только в игнорируемом приватном каталоге проверки. Этот отчёт содержит только безопасные результаты.
