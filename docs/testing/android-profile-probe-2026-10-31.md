# Android: проверка выбранного профиля — 2026-10-31

Локальный checkpoint ветки feat/connection-reliability-ux, база 4bbef70. Продолжение [технического доказательства изоляции](android-isolation-2026-10-31.md). Это продуктовая проверка выбранного профиля; полная D3, диагностика активной Android-сессии и релиз остаются открытыми.

## Поведение

- На главном экране Android добавлена карточка «Проверка выбранного сервера» с проверкой и отменой. Основная кнопка VPN остаётся первой.
- Результат относится к конкретному источнику и его ревизии, виден в карточке и списке серверов. Успех выбранного кандидата не объявляет действующее VPN-подключение проверенным.
- Проверка работает в отдельном закрытом процессе :profile_diagnostics, без TUN и изменений системного прокси. Сохранённая конфигурация и политика маршрутизации приложения не переписываются.
- Rust разрешает источник и передаёт секретную конфигурацию напрямую native-службе. Внутренний runProbe недоступен из WebView; клиент получает только безопасный результат.
- sing-box использует физическую сеть через Android Network API. Xray использует собственное ядро и частный авторизованный libbox SOCKS-переход для физических соединений. Подмена ядра отсутствует.
- HTTPS проверяет сертификат, имя узла, ожидаемый статус и ограничивает ответ; перенаправление не считается успехом. Общий срок 12 секунд, завершение ресурсов ограничено ещё 2 секундами.
- Отмена, изменение каталога, настроек или физической сети делают старые результаты недействительными. Изменение DNS/маршрутов при прежнем Network handle также учитывается.
- Неоднозначные или неподтверждённые готовые конфигурации возвращают «проверка недоступна». Provider DNS не заменяется произвольным рабочим DNS ради зелёного результата.
- Новые сообщения переведены на RU/EN/zh-CN. Карточка сообщает о недоступности контрольного запроса, не выдавая её за доказанную ошибку ключа.

## Найденные ошибки и ревью

Независимое read-only ревью: 0 Critical, 3 Important, 0 Minor. Все три Important исправлены за один проход:

1. Поздняя публикация Xray-владельца после отмены могла оставить процесс. Реестр ресурсов теперь окончательно закрывается, поздно переданный владелец сразу закрывается. JVM RED → GREEN.
2. Прежний идентификатор Network не замечал изменения DNS/маршрутов. Ключ теперь включает существенное состояние физической сети; JVM RED → GREEN.
3. Смена настроек могла вернуть старый успешный snapshot. Завершённый native-результат очищается, UI отвергает отозванные operation IDs; JVM/frontend RED → GREEN и реальный DNS UI-test PASS.

На устройстве отдельно выявлен слишком длинный путь Unix command socket libbox. Частный каталог сокращён; тот же продуктовый запрос после исправления прошёл. Регрессии отклонения HTTPS redirects и различения selected/active evidence также подтверждены RED → GREEN.

Reviewer проверял исходники; телефонную матрицу выполнял основной исполнитель. Новый воспроизводимый runner добавлен после ревью и проверен реальными прогонами. Ревью не заменяет device evidence.

## Воспроизведение

Только на разрешённом устройстве с работающим VPN, debug CloakWire и установленным test-only helper из scripts/android-device-probe:

```text
node scripts/android-profile-probe-check.mjs --adb <adb> --serial <device> --output <private-report.json> --probe-engine singbox --exercise-vpn
node scripts/android-profile-probe-check.mjs --adb <adb> --serial <device> --output <private-report.json> --probe-engine xray --exercise-vpn
```

Runner не переключает действующий VPN; для матрицы повторить при другом активном ядре. Временный локальный Xray-сервер берётся из bundled Windows binary либо передаётся через --core. Все пользовательские резервные копии и подробные отчёты остаются в игнорируемом .superpowers; ключи, профили и ответы серверов в Git не добавляются.
