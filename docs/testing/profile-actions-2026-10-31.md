# Результаты в списке серверов и действия ошибок — 2026-10-31

Контрольная точка B4 в ветке `feat/connection-reliability-ux`, поверх `91081a0`. Пользователь запросил результаты проверки в списке, обновление подписки и переподключение из карточки ошибки; подключённый телефон разрешён для установки и проверки. Весь roadmap этим этапом не завершён.

## Поведение

- Windows/macOS: строки ручных серверов, ссылок подписок и готовых профилей показывают имеющийся результат проверки принятой сессии. У результата есть время и, для подтверждённого доступа, задержка. Отсутствующий, чужой или устаревший результат не становится зелёным.
- Android: строки показывают результат проверки конфигурации перед запуском. Успех подписан «Профиль проверен · доступ не проверялся». Это не сетевой probe и не подтверждение доступности сервера.
- Результат связан с точным источником и SHA-256 его содержимого. Замена позиционного элемента подписки или изменение ручного профиля не наследуют старый успех. Через 60 секунд результат обозначается устаревшим.
- Карточка предлагает переподключить исходный сервер; обновление доступно только для исходной подписки. Изменённый/удалённый источник требует выбора сервера. Двойной клик не создаёт второй запрос.
- Переподключение использует существующий проверяемый запуск без предварительного Stop. Ошибочный кандидат сохраняет работающий VPN.
- Контекст сессии фиксируется вместе с ошибкой: старая карточка не получает права заменить новое подключение. Подготовленный запрос отменяется при изменении каталога.
- Подписки публикуют согласованные summary и полные outbound-данные. Несовпадение содержимого при конкурентном обновлении не связывает старую ревизию с новым сервером.
- Действия и подписи переведены на RU/EN/zh-CN; кнопки имеют область нажатия не меньше 44 px.

В Android владельцем результата/сессии является native service, а не WebView. При старом запуске без сведений об источнике показывается отсутствие проверки. Полноценное пересоздание Activity этим этапом отдельно не доказывалось.

## Установленный Android APK

Устройство CPH2747, Android 16, arm64. Установлена тестовая сборка с существующей версией 1.4.9; это не опубликованный релиз. SHA-256 APK:

`7b370a960e1069b2ae405470ea87c39df22ffbe19bb4b031fc711b7bf506850c`

Перед установкой сохранены предыдущий APK, localStorage и исходная полная конфигурация; подпись нового APK совпала. Обновление выполнено через `adb install -r`, данные не удалялись. Полный tar снимок активных данных имел повреждённый хвост и не считается годной полной резервной копией: используемая исходная конфигурация извлечена отдельно и проверена как JSON.

На итоговом APK подтверждены:

1. Отрицательная проверка кандидата сохраняет текущую сессию.
2. У ручного профиля нет действия обновления подписки.
3. Кнопка карточки действительно переподключает исходный источник с тем же содержимым.
4. В списке появляется отметка проверки профиля с явным ограничением области.
5. Изменение каталога отменяет ранее выданный native preparation token; текущая сессия сохраняется.
6. Карточка чужой/старой сессии не заменяет работающий VPN.
7. Профили и настройки остаются неизменными.
8. После сценариев восстановлена исходная полная конфигурация, а не только списки приложений.
9. Новая карточка не переносит пояснение о смене сервера от предыдущей попытки.

Отдельно повторена реальная сетевая матрица: **8 PASS**, первая попытка каждого сетевого случая. Отдельное обычное Android-приложение получает HTTPS 204 через VPN; sing-box и Xray правильно включают/исключают его в режимах «только выбранные» и «кроме выбранных». Ошибочные кандидаты обоих ядер сохраняют принятую сессию. Проверка WebView Cloakwire не использовалась как доказательство захвата VPN.

Команда воспроизведения сетевой матрицы после установки вспомогательного test-only APK:

```text
node scripts/android-device-check.mjs --adb <adb> --serial <device> --output <private-report.json> --exercise-vpn --xray
```

Она требует уже работающий sing-box и поддерживаемые стендом настройки; восстанавливает полную принятую конфигурацию, политику приложений, состояние, ядро, настройки, профили и выбор. После проверки вспомогательный APK удалён, временные ADB-порты закрыты. Телефон оставлен с работающим исходным sing-box. Принятое пользователем отключение при принудительном закрытии задачи не изменялось.

На телефоне просмотрены экран результатов и карточка ошибки. Скриншоты и приватные отчёты остаются в игнорируемом локальном каталоге, в Git не попадают.

## Исправления по ревью и проверкам

Независимое ревью: 0 Critical, 3 Important, 1 Minor. За один проход исправлены несогласованный snapshot подписки, потеря отмены при изменении источника и повторное присвоение старой карточке текущего контекста сессии. Минимальный текст результата увеличен до 12 px.

Регрессии до исправлений падали: обновление ревизии подписки, отмена native ticket при изменении каталога, старый stopped-контекст. На реальном устройстве дополнительно обнаружена отсутствующая capability `beginProfilePreparation`: добавлено точное разрешение и тест соответствия bridge/ACL. Тест отмены сначала терял structured error на границе Playwright; перехват ошибки внутри WebView подтвердил настоящий `profile_check_cancelled`, изменения runtime для этого не понадобились.

Стенд выбирает процесс Android user 0 по PID/USER/NAME, вместо первого одноимённого PID (на телефоне есть отдельный root-процесс с тем же именем). Отдельная регрессия сначала падала, затем прошла. При финальном просмотре также исправлен перенос пояснения предыдущего действия в новую карточку: браузерная регрессия RED→GREEN, сообщение сбрасывается при смене источника/контекста/попытки.
